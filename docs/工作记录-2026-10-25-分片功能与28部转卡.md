## 2. 工具：`tools/split-m4s.py`

原来只有 PowerShell 版 `tools/merge-split-m4s.ps1`；应用里要能加载，所以补了 Python 版。

- 参数：`split-m4s.py <视频> [-a <音频>] [-n 段数=6] [-o 重叠秒=10] [-d 输出目录] [--name 名称] [--no-full]`
- 五个阶段：`[1/5] 合并` → `[2/5] 关键帧` → `[3/5] 切段` → `[4/5] 自检` → `[5/5] 清单`
- 切点用 `bisect` 对齐到不超过目标时间点的最近关键帧；切段一律 `-c copy`：
  `-ss <start> -i <完整.mp4> -t <dur> -c copy -avoid_negative_ts make_zero -movflags +faststart`
- **自检按"实际切到的位置"算重叠**：`prev_real_end = plan[n-2]["real_end"]`，第 1 段豁免
  （它的起点就是 0，没有上一段）。早期版本拿 0 去和重叠阈值比，导致第 1 段永远"不合格"。
- 清单写**实际**时长与终点，并注明：`-c copy` 只能切在关键帧上，实际比计划最多多一个 GOP，
  所以重叠只会更多、不会更少。
- 进度用 `##CAMMOV {"k": "stage|prog|done"}` 报给界面；取消看 `.probe/cancel.flag`。
- 自测：40 s 单文件 → 3 段（重叠 11.626 / 13.459 s，1.9 s 跑完）；
  DASH 形态（`_v.mp4` 视频 + `_a.mp4` 音频）→ 2 段（重叠 8.334 s）。两次都 exit 0。

### 5.1 中断与续跑（2026-11-01）

- 2026-10-25 16:15 转到第 5 片时**整个跑批进程被宿主一起终止**（片 5 的三个分段同时报
  「分段编码失败」），已完成 1–4 片且门禁都在。
- 续跑就是再跑同一个驱动：它按 `DSC_97xx.MOV` 是否存在跳过已完成片，只补第 5、6 片并
  复核 1–4 片。这次给跳过分支打了补丁 —— **从工具日志里把上次的真实用时捞回来**
  （`"seconds": …`），否则汇总表里跳过片会显示 0 分钟。
- 第二次 14:15 启动、15:13 完成，54.7 分钟（含 4 片重跑门禁）；片 5 用 22.69 分、片 6 用
  20.75 分。E: 当时只剩 24.1 GB，6 片合计 4.96 GB，没到红线但值得盯。
- 教训：跑批**别挂在会被一起收掉的宿主里**。DSH 后台作业能活过会话中断；用
  `Start-Process` / `ProcessStartInfo` 起的"独立"进程反而被宿主作业带走，而且
  `Start-Process` 在本机还会因 `HTTP_PROXY` 与 `http_proxy` 键冲突直接抛异常。

## 6. 本轮新增的坑

- `edit`/`write` 会吃掉 UTF-8 BOM → 改完 `.ps1`/`.cmd` 用
  `[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($true)))` 补回。
- PowerShell 控制台默认 GBK，打印中文（尤其 `❌`）会 `UnicodeEncodeError`；
  查文件结构用 `grep`/`read` 工具，别用 shell 打印中文。
- pip 装 PyInstaller 时本机 Clash 代理（127.0.0.1:7897）没开 → `ProxyError`；
  清 `HTTP_PROXY`/`HTTPS_PROXY`（含小写）后 `pip install --isolated -i <镜像>`。
- dsh 运行时的 python 已不含 PyInstaller，构建改用 `C:\Program Files\Python313\python.exe`
  （PyInstaller 6.22.3 + Pillow 13.0.0），通过 `$env:CAMMOV_PYTHON` 指过去。
