# v0.1.0-beta.3 —— 界面重做（批量 / 合并 / 分片）+ 修掉 29.97 长片的音频分块漂移

把**普通电脑视频**转成**尼康相机能直接播放的 MOV**，带图形界面，Windows 10/11 x64 免安装依赖。

验证机型：**Nikon Z5II**。

## 这一版相对 beta.2 的变化

1. **界面整个重做：从「三张卡 + 高级模式」变成「两张卡 + 一条状态栏」**
   - **删掉高级模式**。一屏只剩：① 来源（选择视频 / 合并视频 + 任务列表）→ ② 画质（三行列表 + 校验开关）→ 底部进度与「开始转换」。模板、封面、分段折进「更多选项 ▾」，日志默认收起。
   - **批量转换**：一次拖进/选进多个文件，逐个转换，每行实时显示「排队 → 转换 45% → 完成 · 43/43」，底部总进度按「做完几个 + 当前进度」算，全程可取消。
   - **合并视频**：选 B 站那种 `.m4s` 视频分片，程序按 `-30064 → -30232`、`-30033 → -30216` 自动配同名音频，先无损合并再转。
   - **转换完自动校验（43 项门禁）**：勾上就每个文件转完立刻校验，标题行显示「完成 · 43/43」；不勾只转换。
   - 输出名自动接在目录里 `DSC_####` 最大编号之后，不会覆盖已有文件。
   - 帧率不再让用户选：源是 30fps/29.97 时自动走 `--fps source` + 29.97 模板，其余 59.94。
2. **修掉一个真 bug：29.97 长片的音频分块漂移**
   - 现象：分块本该**每块 24,024 个音频样本**（0.5 秒），旧版从第 ~512 秒起出现 24,023 / 24,025 交替的块（1377 秒的片子有 441 处）。
   - 根因：`cum = int(cum_v * fps_den / fps_num * 48000 + 1e-9)`，样本累计数超过约 3,300 万（≈90 分钟 @48k，或累计帧数 ≈2^25）后浮点误差超过 `1e-9`，`int()` 向下截断 1 个样本。59.94 与短素材不受影响，所以之前只在 29.97 长片上暴露。
   - 修法：改成整数运算 `(cum_v * fps_den * 48000) // fps_num`；门禁第「分块」项同时从"只比中位数"收紧为"**除末块外每块都等于 0.5 秒**"。
   - 已经产出的旧文件（剧情长片那批）**需要重转**才是整齐的，重转命令见 `docs\工作记录-2026-10-07-彻夜之歌6部转卡.md` §十三。
3. **封面默认「自动」**：先试首帧，首帧是纯色（白场/黑场，比如很多剧集开头的闪白）就退到第一个有内容的帧（判据：160px 缩略图亮度标准差 > 12），再不行才用首帧。也可以手动选「首帧 / 末尾一帧 / 指定图片」。
4. **分片进界面**：「更多选项 → 分段」> 1 时，长片先按关键帧切段再转；也可以在「合并视频」页只做合并、不进转换。
5. 其它：输出目录不存在时自动创建；冒烟报告只认**真正传给转换核心的 argv**（不读界面控件）。

包内还有：`测试指引.txt`（一页纸）、`自检.cmd`（双击按提示跑三步自检并写报告）。

## 已知限制

1. **慢**：编码占 97%+ 时间，本机（i5-12450H）约 0.9~1.0× 实时；1080p 23 分钟动画约 21~37 分钟。
2. **必须重编码**，无法无损转封装（码流参数集必须与相机一致）。
3. **不能用 GPU**：实测 NVENC 与相机差 16 个字段，其中 14 个改不了。
4. **必须有一段相机自己录的同规格 MOV 当模板**（照抄容器结构、时间基、缩略图量化表）；随包两个。
5. **只验证了 1080p** 的 59.94 与 29.97；4K 未实测、工具未放开。
6. **超长片（20 分钟以上）相机能播，但快进越界时不一定会「夹紧」**（会跳到文件头而不是停住）：254 秒能夹、1377 秒不行，原因未查清，正式使用建议切成 15 分钟左右的段。
7. 结论是**逆向推导**出来的，不是厂商文档；**相机固件更新后可能失效**。
