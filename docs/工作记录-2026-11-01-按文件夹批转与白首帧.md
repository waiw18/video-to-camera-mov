# 2026-11-01 按文件夹批转：m4s 对 → 相机 MOV（29.97fps / 不分片）

需求（用户原话）：「把文件夹1，2中合并转换30fps5mbps，不分片」；随后「跑完1不用跑了」→ 只做文件夹 1。

## 结果

| 项 | 值 |
|---|---|
| 源 | `1\23236692_da3-1-30033.m4s`（HEVC 600×480 25fps，86,910,676 B，1854.88 s）+ `23236692_da3-1-30216.m4s`（AAC 44.1k 立体声，15,564,004 B） |
| 合并 | `1\23236692_da3_完整.mp4` 98.5 MB / 1855.04 s（`-c copy -movflags +faststart`） |
| 产物 | `1\相机转换输出\DSC_9738.MOV` **1,044,524,763 B**，1854.946 s，用时 33.85 分钟（0.911×） |
| 实测码率 | 视频 2,196,972 bps + 音频 2,304,000 bps = **4.50 Mbps**（目标 5 Mbps，欠码） |
| 门禁 | **43/43**（mdat 抬到 917,504 = 7×128 KiB；视频 3,706 块×15 帧；音频 3,706 块，末块 28,509）+ 附加 **20/20** |
| 缩略图 | 取**源第 1 秒**那帧；NCTH 与该帧 MAD 0.60、与第 0 帧 MAD 52.14 |

配方：1920×1080 / `--fps 30000/1001` / x265 / PCM 24bit 48k / `--bitrate 5M` / `--preset fast` / `--jobs 3` / `--template templates\DSC_8960.MOV`。

## 三个坑

1. **首帧是纯白闪白帧**：这两个源第 0 帧整屏白（亮度 253/255，min 252 max 253），直接取首帧缩略图就是白方块。做法：按 0/1/2/3/4/5/6/8/10/12 s 抽样，取**亮度标准差 > 12 的第一帧**（本片命中第 1 秒，亮度 201.2、标准差 70.0），日志里写明取了哪一秒。
2. **ABR 在"上采样软画面"上会欠码**：源 600×480 放大到 1080p，内容极好压，x265 ABR 只出 2.20 Mbps（合计 4.50 Mbps），达不到 5 Mbps。要撑满只能调高 `--bitrate`（如 8M），或接受更小的文件。
3. **宿主会回收"独立进程"**：`Start-Process` 在本机还会因 `HTTP_PROXY`/`http_proxy` 键冲突直接抛错；改用 `[System.Diagnostics.Process]::Start()` 起来的进程，在本次 pwsh 调用结束时会被一起收掉。**只有 DSH 后台作业（run_in_background）能活过调用结束** —— 这也是上一次跑批"转到一半整批消失"的原因。
