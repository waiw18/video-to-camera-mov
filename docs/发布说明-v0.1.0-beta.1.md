# v0.1.0-beta.1 —— 第一个打包测试版

把**普通电脑视频**转成**尼康相机能直接播放的 MOV**，带图形界面，Windows 10/11 x64 免安装依赖。

首个验证机型：**Nikon Z5II**（1920×1080 / 59.94fps / H.265 / PCM 24bit）。

## 这一版有什么

- **图形界面**（`app/main.py`，tkinter）：普通模式用真机验证过的配方；高级模式每一项可调，
  会破坏相机兼容性的项（编码器、并行段数、mdat 分块、模板 tkhd 时长）标成"已锁定"并写明原因。
- **三步流程**：① 开始转换 → ② 校验门禁（43 项，必须 43/43）→ ③ 拷到卡上（拷完回读 SHA256 比对）。
- **进度与预计时间**：转换工具通过 `##CAMMOV` 机器可读协议回传阶段、百分比、编码速度、剩余时间
  （剩余时间 = 剩余时长 ÷ 实测编码速度）。
- **缩略图可选**：首帧（默认）/ 指定时间点 / 用一张图片，三张一起换成相机规格 JPEG。
- **可取消**：转换中点"取消转换"会停掉 ffmpeg 并清掉中间文件。
- **两个自检入口**：`--selftest` 和 `--auto`（整套转换 + 门禁跑一遍，结果写报告文件）。

## 下载

| 文件 | 说明 |
|---|---|
| `video-to-camera-mov-v0.1.0-beta.1-win64.zip` | **推荐**。解压得到「相机视频转换器」文件夹（约 400 MB），启动快 |
| `video-to-camera-mov-v0.1.0-beta.1-onefile.exe` | 只有一个文件，第一次启动要解压临时目录，慢一些 |

两个都不需要装 Python 或 ffmpeg（ffmpeg / x265 已打进包里）。
解压/放置位置要放在**桌面、D 盘等普通目录**，别放 `C:\Program Files`
（程序要在自己旁边写转换中间文件）。

包内还有：

- `测试指引.txt` —— 一页纸测试指引（看哪些、怎么回传结果）
- `自检.cmd` —— 把一段短视频拖到它上面，自动跑内置自检并把结果写成
  `smoke-report-ui.txt` / `smoke-report.txt`

## ⚠️ 8 Mbps 档（本版已去掉，但结论已作废）

早期一次 8 Mbps 测试记下了「能转出来、**43 项门禁也全过**，但相机提示"无法显示此文件"」；
**那次没有留下产物或日志**，原因至今未查清（也可能是拷贝不完整之类的外部因素）。
2026-10-07 复核：**5 Mbps 的产物在相机上正常播放**（`DSC_8965`，43/43 门禁），
所以"码率低于 15 Mbps 会被拒"这个说法**作废**。本版预设只留 15M / 40M 是保守选择；
想更小可以自己填 `--bitrate 5M`。

## 已知限制

1. **慢**：i5-12450H 上 4 分钟视频约 20 分钟（编码占 97%+）。
2. **必须重编码**，无法无损转封装（码流参数集必须与相机一致）。
3. **不能用 GPU**：实测 NVENC 与相机差 16 个字段，其中 14 个改不了。
4. **必须有一段相机自己录的同规格 MOV 当模板**（工具会照抄它的容器结构、时间基、缩略图量化表）。
5. **只验证了 1080p59.94**；4K 未实测。
6. ~~**1080p30（29.97）没打通**~~ —— **2026-10-07 已打通并真机播放通过**：
   工具加 `--fps source` 并换 29.97 相机模板（`DSC_8960.MOV`）即可，见 README。
7. **短片段（约 1 分钟）在相机里快进越界时不会被夹紧**（全长文件正常）。
8. 结论是**逆向推导**出来的，不是厂商文档；**相机固件更新后可能失效**。

## 回传什么结果最有价值

按 `测试指引.txt` 里的清单来，重点是：**相机里能不能播、时长对不对、音视频同不同步、能不能完整播完**，
以及 `自检.cmd` 生成的报告文件。失败的截图/录像和报告一起回传最好。
